KurtisOrcutt.com — Yola Production Migration Guide

This guide translates the approved Version 4 redesign into a native Yola Sitebuilder+ build. The standalone files in site-v4/ are the visual/content reference.

Do not publish during construction. Keep the existing live site intact until the replacement has been reviewed and redirects are ready.

1. Protect the current site

In Yola Sitebuilder+, open Website Settings and create a named manual backup before making structural changes. Create another backup immediately before final publication.

3. Global design system

Use a midnight/navy base, warm ivory content surfaces, restrained antique-gold accents, serif display headings, clean sans-serif body type, generous spacing, and large editorial photography. Match the Version 4 reference rather than forcing every detail through custom code.

If your Yola plan supports Custom Code, the included yola-sitewide-custom-css.txt is a reference stylesheet. Native Yola blocks should remain the primary implementation because they are easier to maintain and automatically responsive.

4. Page construction

For each page, open the matching Version 4 HTML file and reproduce its content hierarchy using Yola blocks: hero, text, cards/columns, image-and-text, quote/callout, and footer. Preserve the concise copy and the approved navigation. Do not reintroduce the old 20-plus-item top navigation.

5. Media migration

The Version 4 prototype still references four images hosted on the legacy site. Use asset-inventory.csv to identify them. Upload the original high-resolution files into Yola and replace every legacy resource URL before launch.

Production rule: no final page should depend on an image URL from the old site that may disappear when legacy pages are retired.

6. SEO

Use seo-metadata.csv to populate each page's SEO title and meta description. Confirm canonical URLs and search visibility. Keep any staging/test pages hidden from search results.

7. Redirects

Use redirects.csv for the verified legacy pages already identified. In Yola, create 301 redirects from each old path to its consolidated destination. Before launch, inventory all remaining legacy .php pages—especially old gallery and Order pages—and add redirects so bookmarks and search results do not land on 404 pages.

8. Content verification gate

Before publication, verify the exact formal style, post-nominals, academic credentials, OSMTH office wording/dates, chivalric grades/dates, Baronial dignity wording, and public contact information. This is the final factual sign-off.

9. QA and launch

Use launch-checklist.txt. Preview every page on desktop, tablet, and mobile; test links; inspect image crops; test redirects; create a final backup; then publish only after owner approval. After publication, test the public domain in an incognito/private browser and monitor for missed redirects/404s.
